== Mission

Demande pilote cross-borough (session document-gradle S-274, option 1) : rendre
possible la **publication depuis la CI** d'un borough. Prérequis identifié :
sous `CI=true`, la convention `education.cccp.build.publishing`
**désactivait la signature** (`SigningPolicy.shouldSign = !isCi`,
`PublishingConventionsPlugin.configureSigning`), alors que Maven Central
**rejette** les artefacts non signés. Un job `publishAggregationToCentralPortal`
en CI aurait donc échoué sans correctif — impossible à corriger côté document
seul (le plugin est distribué à 26 consommateurs).

== Livré — 0.0.8

* `SigningPolicy.shouldSign(isCi, isPublishing, version)` — 3ᵉ dimension :
  * un job de **release** exporte `PUBLISH_ENV_VAR` (`CCCP_PUBLISH=true`) et
    **doit signer** même sur CI (il a importé une clé GPG) ;
  * un job de **test** CI (`isCi && !isPublishing`) **ne signe pas** (pas de
    clé — sinon `publishToMavenLocal` échouerait) ;
  * un build **local** signe ;
  * un `-SNAPSHOT` n'est **jamais** signé.
* `PublishingConventionsPlugin.shouldSign` lit `isPublishing`, et
  `build.gradle.kts` du plugin (inline, `SigningPolicy` pas sur le classpath
  buildscript) applique la même règle.
* BDD `publishing-conventions.feature` : scénario « signs on CI when the job is
  publishing » + `When CI is set and CCCP_PUBLISH is true` ; helper
  `signingProbe()` dédupliqué des deux steps de signature.
* Hygiène : `WorkspaceBom.FALLBACK_VERSION` 0.0.58 → **0.0.59** (aligné sur le
  catalogue publié MEMPHIS `6aa2387`) ; `libs.versions.toml` idem.

Baby-step TDD strict : `SigningPolicyTest` réécrit d'abord (5 UT, nouvelle
signature) → RED (compile) → implémentation → GREEN (compile) → REFACTOR.
