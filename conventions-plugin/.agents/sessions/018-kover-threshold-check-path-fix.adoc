== Contexte

Mission déclenchée par `bakery-gradle` (Bushwick) : le PROMPT_REPRISE S-245
(bakery) a retenu la « correction racine conventions » (le chemin de rapport
kover). Le bug était connu côté bakery (S-243 V7) mais classé « hors périmètre »
deux fois ; bakery était **le seul consommateur** de la convention kover, le
workaround local masquait le bug.

== Le bug

`KoverConventionsPlugin.kt:69-72` (0.0.4) lit un chemin **hardcodé**
`build/reports/kover/xml/report.xml`. Or le plugin kover `0.9.8` écrit
`reports/kover/report${variant}.xml` (sources
`kotlinx/kover/.../commons/Paths.kt:30` `xmlReportPath`), soit
`reports/kover/report.xml` pour le variant total. Le `koverThresholdCheck`
échouait donc systématiquement (`Kover report not found`).

== Le fix (baby-step DDD/TDD/BDD)

. **DDD** — `build.KoverCoverage` (objet pur, zéro Gradle) : `summarize(xml)`
  → `Summary(missed, covered, percent)` + `meetsThreshold(xml, threshold)`.
  Sémantique : les compteurs `INSTRUCTION` sont répétés à chaque niveau
  (parent = somme des enfants), le ratio est invariant sous la hiérarchie.
  `KoverCoverageTest` : **6 UT**.
. **TDD** — `resolveXmlReportFile(project)` lit la propriété **réelle**
  `kover.reports.total.xml.xmlFile` (source de vérité, robuste à une surcharge
  `xmlFile`), fallback défaut kover. `KoverThresholdCheckFunctionalTest` :
  **2 FT** (RED `Kover report not found` → GREEN).
. **BDD** — `kover-threshold-check.feature` **3 scénarios** + steps TestKit.
  RED prouvé par revert ciblé (2/3 échouent avec le chemin hardcodé) → GREEN.

== Découverte annexe — bug latent `configureKover` no-op

Le helper `invokeMethod(target, clazz, "currentProject")` cherche la méthode
`currentProject` (sans préfixe `get`), or Kotlin compile `val currentProject`
en **getter Java `getCurrentProject()`** → la méthode n'est **jamais trouvée**,
`invokeMethod` retourne `null`, et tout `configureKover`
(`includedSourceSets = {main, functionalTest}`, `html.onCheck`, `xml.onCheck`)
est **silencieusement no-op**. C'est pourquoi bakery devait tout configurer
lui-même via son workaround.

**Non corrigé** en S-018 : l'intention exacte de ce code mort est ambiguë
(`includedSourceSets = {main, functionalTest}` exclurait `e2eTest` de la
