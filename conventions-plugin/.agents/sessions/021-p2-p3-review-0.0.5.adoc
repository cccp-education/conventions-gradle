== Baby-step DDD/TDD/BDD

=== P2-A — anti-drift par construction (DDD/TDD/BDD/FT)

* **DDD** — `build.WorkspaceBom` objet pur : `coordinates(version)`,
  `version(loader)` (lecture ressource, fallback si absente/blanche),
  `coordinates(loader)`. Aucun type Gradle → unit-testable.
* **Source unique** — la version vit dans `gradle/libs.versions.toml`
  (`[versions].workspace-bom = "0.0.58"`) et est matérialisée en ressource
  (`build/workspace-bom.properties`) par la tâche `generateWorkspaceBomInfo`.
  Le fallback codé **ne peut plus** dériver silencieusement : la garde vérifie
  ressource == fallback.
* **TDD** — `WorkspaceBomTest` 7 UT (composition, lecture, absence, blanc,
  coordonnées via loader, fallback == version publiée, garde anti-`0.0.13`).
* **BDD** — le scénario « Fallback versions are up-to-date » n'asserte plus la
  version en dur : il lit `WorkspaceBom.coordinates(...)` (c'est exactement le
  hardcode qui avait laissé passer le drift).
* **FT** — `WorkspaceBomFunctionalTest` (2 tests) : la version est **injectée
  par Gradle** (`systemProperty("conventions.workspaceBom.version", …)`, patron
  graphify D5-RACE) ; un consommateur sans catalogue reçoit la version courante
  et jamais `0.0.13`.

=== P2-B — opt-in explicite (DDD/TDD/BDD/FT)

* **DDD** — `additionalTasksInCheck: Boolean = false` sur l'extension, documenté
  (un consommateur à 22 runners comme capsule garde `check` rapide ; ces runners
  sont déjà exécutés par le workflow CI `full-tests`).
* **BDD/FT** — 2 scénarios + 2 FT pilotés par `check --dry-run` : par défaut le
  runner additionnel n'apparaît pas dans `check`, et y apparaît quand l'opt-in
  est activé.

=== P3-1 — vérification empirique

La review soupçonnait la mutation `startParameter.isBuildCacheEnabled` d'être
hostile au configuration cache. Le comportement a été **vérifié** : le
configuration cache est stocké au 1er run puis réutilisé au 2e. Aucun changement
de comportement ; KDoc explicatif ajouté (une réécriture `settings.buildCache`
n'est pas exposée publiquement à un plugin `Project`).

=== P3-2 — assertions factices supprimées

`GradlePluginConventionsSteps` enregistre une sonde `probeConventions` dans le
projet consommateur jetable ; chaque `assert(true)` devient une assertion réelle
sur l'extension ou sur la `Test` task matérialisée. Les placeholders restants
`assert(true)` sont des **smoke tests** d'un projet jetable interne (pas des
assertions BDD de production).

=== P3-3 — câblage robuste

`LintConventionsPlugin` câble désormais `check` via `tasks.matching { name ==
"check" }.configureEach { … }` : le câblage survit à l'enregistrement tardif de
la tâche `check` (base/java appliqués après le plugin), là où l'ancien
`findByName(...)?.dependsOn(...)` en `afterEvaluate` échouait silencieusement.

== Preuve de validité — Local = Build, Tests = CI
