== 1. Investigation — JitPack

Sources primaires : `docs.jitpack.io` (About, Building), articles de référence
sur le JDK récent, le groupId personnalisé et le `plugins {}` DSL.

[cols="2,5"]
|===
| Point | Résultat

| Mode
| Build **à la demande** depuis un tag/commit/branche d'un dépôt **public** ;
  aucun upload ni credential. `./gradlew build publishToMavenLocal` par défaut,
  surchargeable par `jitpack.yml`.

| JDK
| **JDK 8 par défaut** → installer JDK 25 via SDKMAN en `before_install`
  (`sdk install java 25-tem` + `sdk use java 25-tem`). `jdk:` seul est
  insuffisant.

| Multi-module
| `com.github.USER.REPO:MODULE:VERSION` (module = `artifactId`). Le **nom du
  dépôt** est l'artifactId de référence.

| Plugins DSL
| **Pas de marqueur de plugin** au groupId de l'id → shim obligatoire
  `pluginManagement.resolutionStrategy.eachPlugin { useModule(...) }`.

| Signature
| Aucune signature GPG/checksums ; immuabilité après 7 jours.

| GroupId personnalisé
| DNS `TXT git.<domaine>` → `https://github.com/<org>` (option P2, coordonnées
  multi-module à valider).
|===

=== Preuve locale du shim

Consommateur `/tmp/opencode/jitpack-probe` : `useModule(
"education.cccp.build:conventions-plugin:0.0.14")` + application de
`education.cccp.build.lint` → **BUILD SUCCESSFUL** (Gradle 9.8.2, JDK 25.0.5).
Le mapping id de plugin → module unique fonctionne ; il reste à pointer vers
les coordonnées JitPack.

== 2. Contraintes du dépôt (mesurées)

* Racine `conventions-gradle/` = **aucune publication** ; le build réel est le
  **sous-build** `conventions-plugin/` → `install` doit utiliser
  `-p conventions-plugin`.
* `version = "0.0.14"` **codée en dur** → un tag `v0.0.15` publierait 0.0.14.
  Correctif : `-Pversion="${VERSION#v}"` + lecture de la propriété.
* `signing` s'active si `CI != true` → JitPack (sans GPG) échouerait ;
  `env: CI: "true"`.
* 8 marqueurs de plugin générés mais non servis au groupId attendu → shim
  `useModule`.
* Stack Java 25 / Kotlin 2.4.10 / Gradle 9.8.2.

== 4. Verdict d'investigation

JitPack est **techniquement viable** comme canal secondaire sans credential.
Les deux seuls points non prouvés (JDK 25 dans l'image, coordonnées exactes du
module) se lèvent par un **unique build réel** (US-2) ; le mécanisme Gradle
côté consommateur est déjà prouvé localement (US-0).

Point d'attention majeur : **JitPack ne fournit pas la résolution `plugins {}`
native** (pas de marqueur de plugin) — chaque consommateur doit ajouter un shim
`useModule`. C'est acceptable pour un canal de secours, pas idéal comme canal
primaire pour des plugins OSS destinés à des tiers.
