== Baby-step DDD/TDD/BDD

=== P1-A — CI (infrastructure)

Pas de test : c'est la **preuve de validité** elle-même. Le workflow suit le
patron des boroughs voisins (bakery, codebase) : `actions/setup-java@v4`
JDK 25 temurin, `gradle/actions/setup-gradle@v4`, `./gradlew check` depuis
`conventions-plugin/`.

**Blocage découvert** : `settings.gradle.kts` faisait
`error("ossrhUsername not found")` quand `~/.gradle/gradle.properties` est
absent — ce qui est toujours le cas sur un runner CI. Le build échouait **en
configuration**, avant toute tâche de test. Fix aligné sur `workspace-bom` :
fallback `?: ""` (la publication échoue toujours bruyamment si les creds
manquent).

=== Bug signature — DDD/TDD/BDD (révélé par le CI)

Le **premier run CI** (`36349502503`) est rouge : `:test` 53/1 et
`:cucumberTest` 49/1, un seul scénario fautif — « Publishing plugin signs
publications conditionally » (`PublishingConventionsSteps.kt:120`,
`AssertionError: Expected signing tasks in output`).

**Cause racine** : le scénario teste la branche *non-CI*
(`shouldSign = !isCI && !snapshot`), mais **GitHub Actions exporte `CI=true`**.
Le test ne pouvait passer qu'en local — précisément le trou que l'ajout du CI
devait révéler (règle *Local = Build, Tests = CI*).

* **DDD** — `build.SigningPolicy` objet pur (`shouldSign(isCi, version)`,
  `CI_ENV_VAR`), sans type Gradle. `PublishingConventionsPlugin.shouldSign`
  délègue.
* **TDD** — `SigningPolicyTest` 4 UT (non-CI non-snapshot, CI, snapshot,
  snapshot+CI).
* **BDD** — le step `CI is not set …` positionne `ciUnset` ; le Then fork
  TestKit avec `withEnvironment(System.getenv() - "CI")` (environnement complet
  préservé, seule la variable `CI` retirée) → déterministe en CI comme en local.
